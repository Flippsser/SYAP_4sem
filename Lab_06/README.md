# Лабораторная работа N6

Тема: многошаговая регистрация на React, useReducer и Zod.

## Запуск

```bash
npm install
npm run dev
```

Проверка сборки:

```bash
npm run build
npm run lint
```

## Реализация

- Форма состоит из трех шагов: аккаунт, профиль, о себе.
- Все данные формы и ошибки управляются через `useReducer`.
- Тип данных формы выводится из `RegistrationSchema` через `z.infer`.
- Для каждого шага используется схема на основе `.pick()`.
- Валидация выполняется через `.safeParse()`.
- Финальная отправка имитируется через `setTimeout` на 2 секунды, данные выводятся в консоль.

## Контрольные вопросы

1. Четыре роли Flux: Action, Dispatcher, Store, View. Центральный узел - Dispatcher, он принимает action и рассылает уведомления store.
2. Однонаправленный поток данных означает движение данных по цепочке View -> Action -> Dispatcher -> Store -> View. Store нельзя изменять напрямую из View.
3. Три основные части useReducer: reducer, initialState и dispatch. Без них хук не сможет хранить состояние, вычислять новое состояние и принимать команды.
4. Reducer в функциональном программировании - чистая функция, которая по текущему состоянию и action возвращает новое состояние. Чистота важна, потому что результат должен быть предсказуемым и не зависеть от побочных эффектов.
5. Dispatch отправляет action в reducer и запускает пересчет состояния.
6. Типизация Action в TypeScript ограничивает список допустимых команд и их payload, поэтому ошибка в названии action или поле данных будет поймана до запуска приложения.
7. Неизвестные action обычно попадают в ветку `default`, где reducer возвращает текущее состояние без изменений.
8. `.parse()` выбрасывает исключение при ошибке валидации, а `.safeParse()` возвращает объект результата с `success`. Для пользовательских форм удобнее `.safeParse()`, чтобы спокойно показать ошибки в интерфейсе.
9. Тип на основе схемы Zod создается через `z.infer<typeof SchemaName>`.
10. `.pick()` и `.partial()` позволяют переиспользовать базовую схему для отдельных частей формы или API: выбрать нужные поля либо сделать часть полей необязательными.
